Reversible workflow

Customize Pi without risking your everyday setup

A separate agent directory and session directory let you experiment in a second Pi process. Your regular install stays the control group.

①

Keep your normal Pi

Your existing ~/.pi/agent, extensions, settings, and sessions remain untouched.

→
②

Launch an isolated copy

Point Pi at a separate config home and session folder. Optionally disable auto-discovered resources.

PI_CODING_AGENT_DIR="$HOME/.pi-lab/agent" \
pi --session-dir "$HOME/.pi-lab/sessions" \
  --no-approve --no-context-files
→
③

Try the customization

Load just the prototype extension in the lab. Iterate there; close the process or remove the lab folder to back out.

PI_CODING_AGENT_DIR="$HOME/.pi-lab/agent" \
pi --session-dir "$HOME/.pi-lab/sessions" \
  --no-approve --no-context-files \
  --extension ./my-extension.ts
Safety boundary — the sandbox isolates Pi configuration and sessions. For edits to an extension, work on a copy or a separate Git branch too; avoid editing files inside your active Pi install.

Commands are examples based on the installed Pi CLI. The separate directory is created as needed. Don’t copy personal credentials into the sandbox unless you explicitly want the test instance to use them.
